# 术语链接词改为生成时由模型选择

## Why

现有术语链接靠读取时启发式挖掘(正则 + 技术词典 + 标识符规则 + 代码索引)猜候选,再按分数阈值决定展示。问题:

1. 把非术语标成链接:加粗强调句("禁止编译器偷偷做类型转换")、句中碎片("它只是把")、示例输出被当成术语,课件上链接泛滥且无意义。
2. 与学情脱节:不知道学习者掌握情况,把所有入门者当新手,大量已确认掌握的术语仍被标出。
3. 重复请求:读文档时若候选不足还要再调一次模型补扫;同一文档桌面/安卓各维护一套启发式(backend `_local_candidates` 与 android `localTermCandidates` 双份词典)。

## What Changes

1. 链接词在**生成时**决定:课件(总纲/子总纲/学习计划课/文件课)与 QA 回答生成时,模型结合学习画像自主输出 `TERMS: [...]` 元数据行(每课每节 0-3 个、回答最多 12 个),正文与术语同一次生成确定。
2. 删除读取时启发式挖掘:后端 `_local_candidates`、前端/安卓正则词典候选、依据候选择补扫的自动模型扫描全部移除;生成产出直接登记为术语并按整批替换(空选择也生效),不另发模型请求。
3. 展示信任模型选择:仅保留安全护栏——不装饰代码块/已有链接/标题,inline code 必须整 span 匹配,整词边界校验;学情覆盖:手动 known/confirmed 隐藏、手动 unknown 突出、model 选择默认 subtle,只受阅读密度与去重限制;手动显式链接永不被删且不占预算。
4. 学情入上下文:后端/安卓新增 `term_learning_context` 注入(known / needs_support 名单 + 项目主题),生成与问答都收到;新增 `knowledge_status` 通道;展示引擎加载中不闪现旧决策(免闪烁)。
5. UI 归并:扫描状态/重扫入口统一为 DocumentTermScanControl(工具栏 + 学习档案弹窗共用),重扫需确认并校验模型授权;轮询只在 queued/running 进行;术语缓存键加 projectId 前缀修复跨项目串扰。

## 非目标

- 不改学习者画像本身的推理(由 personalization 子系统负责,另行跟进)
- 不做任何界面风格/视觉改动(本批次全部为生成、判定与数据逻辑)
