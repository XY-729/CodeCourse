# 统一讲解索引与理解反馈

## 问题
原有术语候选、阅读完成度和知识画像不能完整表达“某个知识点的哪个范围已经在哪里讲过”。总纲、课件和选区回答需要共享历史讲解，且用户需要直接确认理解程度。

## 已实现方案
- 独立讲解索引记录知识点、覆盖范围、能力维度、来源路径、正文摘录、行号和版本。生成时在同次模型输出中提取，不受术语候选数量限制。
- 总纲、课件、问答共享历史上下文。精确匹配且可验证的完整重复段落替换为旧讲解链接；明确要求重讲或仍有疑问时保留解释。
- 引用打开原始文档并定位段落；正文修改导致无法唯一定位时明确报错，不跳转到错误位置。
- 课件和选区回答提供已理解、部分理解、仍有疑问、撤销，支持调整关联知识范围、重复请求幂等和失败重试。
- 理解反馈按知识点、范围、能力维度更新画像；人工理解确认不直接等同掌握。目录阅读完成度和知识理解状态分别显示。
- 历史文档显示待补录，提供单篇和批量补录确认入口。补录调用模型并校验原文摘录，不修改可见正文。
- 桌面及 Android 共用元数据协议和数据库结构；数据归档保留索引、反馈及稳定段落 ID。

## 验收与边界
本实现提供可验证的索引和精确重复保护，不承诺任意模型输出的语义零重复。元数据缺失或摘录无效时显示待补录/不完整，不虚构覆盖记录。上下文最多提供 40 条有效历史片段；历史单篇补录上限 80,000 字符。总纲覆盖保守记为计划内容。既有生成任务缓存规则保持现状，重新打开已生成任务不自动调用模型重写。
Android 已完成前端构建、SQLite 契约及回归测试，未进行 Android 真机或 APK 验证。
