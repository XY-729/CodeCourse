# Android 历史记录界面修复（2026-10-15）

## 已确认的原因及修复

- 历史主题列表使用纵向 Flex 布局，主题卡片同时设置 `overflow: hidden`，却允许压缩。在 360 × 660 的安卓布局、15 个历史主题下，卡片高度被压到约 26.76 像素，70 像素的标题及展开内容被裁掉，呈现空白条。卡片现在保留自身高度，超出部分由列表滚动；折叠高度约 71.33 像素，展开内容及按钮可见。
- 同一会话可以产生多个主题，移动列表原先以会话 ID 为 React key，导致重复标识。现在使用分组函数合并后的主题作为唯一标识，搜索和列表恢复时不再混用节点；搜索及收藏结果自动展开。
- 历史搜索缺少请求次序与项目隔离，旧请求可能覆盖新搜索。后台回调还可能继续使用旧筛选条件，打开项目时另一条全量历史请求也会覆盖正在筛选的列表。新增 `useQAHistory` 统一加载，按当前项目、搜索词、收藏状态和请求序号接收结果；保留全量请求用于阅读位置恢复，不再写入筛选列表。
- 历史读取错误原先只显示在提问页，历史页会误报没有记录。现在历史页显示加载状态、失败原因及重试入口；取消收藏成功后按当前条件重新查询。
- 安卓服务初始化失败后原先永久缓存被拒绝的 Promise，后续页面请求无法恢复。现在失败后允许重新初始化，并捕获启动权限监听器的初始化异常。

此次修改保留已有未提交的安卓流式问答、数据包导入和数据库连接修复，没有调整主题或工作区缩放行为。
