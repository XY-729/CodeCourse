# 00：共同契约

这是后续实现的建议基线，开工前统一冻结。字段名、版本、语义不可由单个模型自行更换。所有任务均继承 [总说明](README.md) 中的范围和文件归属。

## 1. 统一机制

总纲、课件、问答共用：知识身份 → 完整树快照 → 用户明确要求 → 内容与清单同次生成 → 本地校验入库 → 用户反馈 → 本地更新树。

- 内容类型为 outline、lesson、answer。保留现有 source_type=course/qa，以 artifact_kind 区分总纲与课件，避免无必要破坏来源路由。
- AI 负责识别概念、归属、实际讲解范围、术语候选和章节分工。
- 软件负责身份解析、关系验证、证据、幂等、撤销、状态归约、版本和持久化。
- 确认理解、取消理解、课程完成、打开材料、删除来源的正常路径不得调用模型。
- 不保留另一套只给 QA 或只给课件使用的画像真值。

## 2. 概念森林

复用 concepts 作为身份，增加权威父子归属与计划根关联。C++ → STL 容器 → vector；C++ → 多线程。节点成为父节点后，仍有自身知识状态。

- 通用概念属于 global/local-user，私有符号属于 project/project_id。完整树包含全局树与当前项目私有树，不含其他项目私有符号。
- 同一作用域每概念一个主父节点；先修、相关和来源关系独立，不作为额外父节点。
- 多个 C++ 计划关联同一通用根，不因计划改名新建根。
- 新概念先匹配已有合适父概念；小概念缺父时必须尝试自动补齐合理的父/祖先，不能默认独立建根。真正独立的领域顶层才新建根，无法判断时如实记录待归属；不能靠固定词表或名称包含关系猜挂接。
- 拒绝不存在父节点、自环、循环、跨私有项目父子边；同批新节点的父引用必须可解析。
- 允许项目私有子节点挂到全局父节点或同项目私有父节点；禁止全局子节点挂到项目私有父节点，防止全局树依赖不可见祖先。
- 重挂已有节点需要显式结构变更及 topology_version 校验；普通回答不能悄悄覆盖旧父节点。
- 同义词绑定规范概念，保留领域与作用域；禁止跨语言同名误合并。

创建计划允许在创建阶段调用 AI 识别根，这不属于“确认理解后调用 AI”。先持久化计划，根识别成功后关联，失败显示待识别并可重试；不能伪装已有 cpp 根。用户已选定现有根时直接关联。识别根与首次总纲的调用可合并，但若延迟到总纲才建立根，必须如实显示计划根待识别，不能宣称已经满足“创建即有根”。

### 2.1 父概念匹配和缺失祖先自动补齐（必做）

此流程适用于总纲、课件和问答，必须写入生成契约：

1. AI 结合完整树中的规范名、别名、领域、作用域和当前内容，先寻找语义合适的已有概念及最接近的合理父概念；找到则返回已有 ID，不重复创建。
2. 当前知识点是细粒度概念且合理父概念未记录时，在同一次响应里同时返回父概念和子概念；必要时补一段祖先链，直到连接已有合理祖先或合理的新领域根。
3. 仅有过宽祖先时，可补有实际分类意义的中间层。例如树已有 C++，正文新讲 vector，而 STL 容器缺失，应能返回“复用 C++ → 新建 STL 容器 → 新建/复用 std::vector”，而非只能把 vector 设根或直接挂到最宽节点。
4. 只补当前归属需要的合理层级，不无限补到“知识/科学”等无助教学的泛化根，也不把当前树中不相关节点强当父节点。
5. 已有无父小节点也应能自动补父。“显式结构变更”指清单明确提出变更、软件检查版本并应用，不要求用户逐个手工批准。已有有效父边不因一次普通生成被任意重排。
6. 软件落库时再次检查身份和父边；并发新增的同一父概念必须复用。若过期提案与新权威父边冲突，保留当前边并记录待协调冲突，不覆盖、不另造同义父节点绕过冲突。
7. 补建的结构祖先可以没有 coverage、terms 或正文 quote，只记录分类来源；不因此认定讲过/用户懂了。用户理解子概念也不升级这些祖先的熟悉度。

语义匹配和祖先提案发生在生成正文与清单的同一次 AI 响应；确认理解阶段只按已保存并验证的清单更新，不能届时再调 AI 找父概念。

## 3. 用事实表达熟悉度

建议对外使用下列 familiarity 状态，不用未经校准的概率替代事实：

| 状态 | 含义与依据 |
| --- | --- |
| unrecorded | 无用户学习证据；仅计划或仅生成可保持此状态 |
| encountered | 用户打开过材料或问过相关问题，不能据此判定会或不会 |
| studied | 用户对有效文档版本标记已学完 |
| self_reported_understood | 用户确认理解已校验的概念＋范围 |
| partially_understood | 用户明确反馈同一范围只理解了一部分，保留 partial 原始反馈 |
| declared_known | 用户明确手动声明已会，保留声明来源 |
| needs_help | 用户明确表示当前范围仍不懂，保留反馈或原文 |
| mixed | 概念不同范围状态不同的汇总，不抹平逐范围记录 |

独立保存教学覆盖 kind：planned、mentioned、brief、explained，以及 aspect、dimension、来源版本。覆盖说明软件安排或生成过什么；familiarity 说明用户做过何种学习声明或行为。

- 总纲未来目标为 planned；总纲的真实解释可为 brief/explained。
- 生成过不等于读过；打开过不等于学完；确认理解不等于会实现、调试或迁移。
- 普通追问、重复打开、停留时间、术语曝光不自动变成不懂或掌握。
- 打开整篇文档只记文档级打开事实；只有明确询问、选中或实际定位到的概念范围才可投影 encountered，不能把清单所有概念自动算作接触。
- 当前明确困惑优先用于当前教学，保留历史正向证据而非抹掉。
- 不沿父子树传播状态。
- 旧概率保留作历史兼容也不能决定新状态；已有真实能力证据另存，不从“懂了”自动加能力分。

partial 是同一范围的部分理解，不等于不同范围状态不同的 mixed；两者均须独立保留。

## 4. 同次生成的 TeachingManifest v2

升级已有 TEACHING 隐藏元数据，不平行另建一套清单。旧数组视为 legacy 格式。建议新对象使用固定 snake_case：

~~~json
{
  "schema_version": 2,
  "concepts": [
    {
      "ref": "cpp",
      "existing_id": "上下文提供的真实ID",
      "name": "C++",
      "domain": "cpp",
      "scope": "global",
      "parent_ref": null,
      "aliases": ["cpp"]
    },
    {
      "ref": "stl",
      "existing_id": null,
      "name": "STL 容器",
      "domain": "cpp",
      "scope": "global",
      "parent_ref": "cpp",
      "aliases": []
    },
    {
      "ref": "vector",
      "existing_id": null,
      "name": "std::vector",
      "domain": "cpp",
      "scope": "global",
      "parent_ref": "stl",
      "aliases": ["vector"]
    }
  ],
  "coverage": [
    {
      "concept_ref": "vector",
      "aspect": "连续存储与基本访问",
      "kind": "explained",
      "dimension": "conceptual",
      "core": true,
      "quote": "本次正文中逐字出现且可以唯一定位的实际讲解片段"
    }
  ],
  "terms": [
    {
      "concept_ref": "vector",
      "text": "vector",
      "quote": "含该原词且可定位的实际上下文"
    }
  ]
}
~~~

约束：

1. ref 只在本次响应内唯一；existing_id 只能引用上下文提供且可访问的真实概念，软件分配新数据库 ID。
2. concepts 包括归属所需祖先；parent_ref 指向同一对象内的 ref。已有节点按 existing_id 复用，正常生成不暗改已有父边。
3. 结构祖先可无 coverage。无原文依据不能标 explained。模型不返回熟悉度、权重或 understood=true。
4. kind 沿用 mentioned/brief/explained/planned；dimension 沿用 conceptual/code_reading/implementation/debugging/transfer。
5. coverage 不限 12 项；terms 为完整技术术语候选池，不按生成开始时的熟悉度先丢弃。
6. source_type、source_path、artifact_kind、content_hash、tree_version、generation_id 由程序绑定，不能信任模型自报。
7. 正文先流式展示，尾部固定输出单行 TEACHING: {...}；JSON 字符串换行须转义，不允许多行裸对象。增量解析器识别跨 chunk 标记并隔离；可保留 TITLE/HANDOFF。
8. 可迁移 Markdown 固定保存为单行 &lt;!-- codecourse-teaching: {...} --&gt;，对象保留 schema_version=2，JSON 内尖括号转义。数据库保存其解析结构和服务端来源/版本字段；派生标注另存，不另建不兼容清单协议。
9. 有效 v2 的 terms 为权威，不由 legacy TERMS 截断或覆盖。v2 已出现但损坏时标 invalid，不能偷偷回退旧数组/TERMS 并宣布全部成功。超解析资源限制明确报错，不静默截断。
10. 跨章节 ref 必须先加 response/section 命名空间，同时改写 parent_ref/concept_ref 及 placement_changes 内的引用，再由身份服务合并规范概念；禁止直接拼接各章 concepts 数组导致同名 ref 串接。
11. 可选 placement_changes 默认为空数组，用于已有节点明确补父/重挂；每项含 concept_ref、from_parent_id（原本为根则为 null）、to_parent_ref、reason。from_parent_id 和服务端绑定的 topology_version 用于比较更新，to_parent_ref 必须在本清单中存在。缺该提案时，已有节点的 parent_ref 不得暗改权威父边。新节点的正常 parent_ref 挂接不需要此额外提案。

content_hash 统一为最终持久化 Markdown 文本的 UTF-8 SHA-256，包含隐藏清单，沿用现有索引口径；新生成统一 LF，已有旧文档按实际持久化文本校验，不在读取时偷偷改换行。模型清单内不含该 hash，避免循环依赖。quote/span 始终按隐藏元数据后的可见正文定位。

版本引用统一为 tree_snapshot={topology_version,state_version}；文档中 tree_version 是这一对版本的简称，不另设含义不同的第三个计数。规划和 writer 冻结同一快照，最终术语重读最新可用快照；拓扑也变化时重新解析概念映射，不能只比较 state_version。

## 5. 保存和确认

新内容有 content_status 与 metadata_status，清单验证成功才可对其知识范围确认理解。

1. 冻结生成时树版本与分工版本。
2. 同一响应取得正文、清单，在本地验证概念归属、权限、quote、术语位置及响应完成状态。
3. 发布过程关联正文、清单、概念、父边、覆盖、术语。SQLite 与文件不共享事务，采用 staging/发布状态或 outbox 恢复，不能假设 SQL 事务覆盖文件系统。
4. 元数据错误时可保存正文草稿并显示“知识清单未就绪”，不能伪装完全成功，也不能提高熟悉度。主动修复属于单独可见生成任务，不能藏在已理解点击里。
5. 反馈继续使用 content_hash、passage_ids、request_key 等现有能力；每次新的用户动作有新 action_id，网络重试复用它。
6. 服务端校验版本、范围并事务写证据及状态投影。整文确认只展开本次实际 brief/explained 范围，planned/mentioned 不升理解。
7. 重复不累计；撤销重算；删除只撤销该来源；重生成、重置、异步迟到不能复活旧证据。
8. 正常新生成不再由后台另一轮 AI 重做清单、术语或熟悉度提取。旧文档补录独立且显式触发，不由确认理解自动触发。

## 6. 完整树与用户要求

每次规划和正文生成都注入当前可用的完整树：稳定 ID、名称、主父关系、事实熟悉状态、实际讲过/理解的范围摘要。详细原文和事件日志另按需要检索。

消息组织建议：固定规则和输出协议 → 稳定拓扑 → 全量最新状态/范围摘要 → 有作用域的用户原文要求 → 当前材料、问题或章节职责。角色和规则仍保证用户要求优先，来源材料只是数据。

- 同树版本序列化字节稳定，无当前时间、随机 ID、最近活跃排序；拓扑按稳定序号，动态状态放后部。
- 当前用户明确要求优先于历史要求；历史原文保留作用域与来源，可编辑删除。
- 不把旧滑块数值转成“用户原文要求”；不重新写固定默认长度、术语密度、原理/例子顺序。
- 去重按 concept＋aspect＋dimension，新的范围、当前疑问和明确重讲正常解释。
- 测真实 token；超预算先无损精简，确实放不下时明确报告并停止该次生成或由用户选后续处理，不能悄悄退回前 8 个概念。
- 缓存依据服务端 usage；未提供命中数据则未知。缓存不是功能正确性的前提。

## 7. 并发课件

复用已有并发协调，形成不可变 LessonResponsibilityMap：plan_id、版本、tree_version，以及每章 section_id、负责的 concept＋aspect＋dimension、只引用项、避免重复项、依赖章和引用目标。

全部 writer 接收完整同一分工表和同版树。不能只传自己的任务；不能把“另一章将讲”当用户已经学会。失败重试复用同版分工；改全局分工则失效受影响旧结果。最终按实际清单检查职责覆盖与重复，不只查名称出现。

## 8. 最终术语与 QA

拼接结束合并完整候选池，对最终正文及最新树版本重新判定；总纲和回答完成时复用同一规则。

- 陌生、待澄清、缺乏充分熟悉依据的术语提供入口；无记录表示未知。
- 当前刚生成解释不证明用户懂了，不能因此移除全部陌生链接。
- 去掉 12/20/24/30 等截断、段落和全文密度配额；保留合法位置、最长词优先、禁止嵌套、手动链接与概念去重。
- “全部”指最终正文中允许标注的可见区域的全部有效技术概念。默认每个陌生概念至少一个入口，按规范概念身份去重；同一拼写在不同语境代表不同概念时分别提供入口，不能只按 text 合并。同概念重复位置可共享入口。
- 代码块、已有链接和隐藏元数据不改写；行内代码、表格、标题中的真实术语应统一支持。
- 用 sidecar/AST 标注，避免插链接反复改变正文 hash。缓存键含文档版本、树状态版本、规则版本，反馈后重算。
- 点击生成解析走普通 QA，附概念、选区、来源版本和历史解释。系统问题可以是“这里的 vector 是什么？请结合当前内容解释”，不强制讲原理、给下一步或固定顺序。

## 9. 删除与保留

删除固定风格控件及其自动推断、偏好问卷、诊断题的新画像写入路径。保留自由要求、学习目标、选材、正常总纲预检、手写总结、手动状态纠正、课程完成和理解反馈。

个性化与证据分析常开，旧 false 不生效。旧 observer 不能绕过权威服务另写猜测能力和固定偏好；常开不等于每次额外调一次观察模型。

旧表可先留作备份兼容，但旧偏好和诊断分数不再进入新教学决策；旧队列不得继续写入。迁移默认不调 AI，无清单的旧内容保持未知/待补录。
