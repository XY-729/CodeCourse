# 完整知识树上下文压缩与请求预算修正

本次把发送给模型的知识树改为紧凑格式，保留完整可见节点、父子关系、熟悉度、具体学习范围和来源信息。数据库中的概念身份、历史证据和导出格式保持原有协议。桌面端总纲、课件规划、并发章节、提问以及现有根识别入口共用新的模型上下文；Android 的知识树上下文同步采用同一短编号算法。

## 格式和回写

- 节点按真实身份排序，发送时使用 `[编号, 概念名, 父编号, 可选覆盖属性]`。领域、作用域等共同属性在 defaults 中声明一次。
- 默认熟悉度为 unrecorded，默认 ranges、coverage 为空；没有覆盖属性的状态行省略。省略表示暂无对应记录，不代表已经掌握。
- 编号由真实 ID 的 SHA-256 前 6 字节经 URL-safe Base64 编码得到，带 `c_` 前缀。增减其他节点不会改变已有节点编号；编号冲突会明确停止处理。
- AI 的 existing_id、from_parent_id 在身份校验前还原；正文、原文引用和本响应 ref 不替换。旧完整 ID 继续兼容。
- 原有身份、项目隔离、换父版本和章节职责校验继续执行。软件保存的冻结规划仍使用真实 ID，重试可以复用同一规划。
- 节点行位于版本与状态之前；只改熟悉度不会改变拓扑前缀。是否命中提示词缓存由服务商返回的 usage 判断。

## 请求预算

旧检查把每个 UTF-8 字节直接视作一个输入 token，容易在发送前拒绝完整树请求。现在使用按文本类型加权、附加 20% 余量的估算；字节上界保留为诊断字段，估算结果明确标记 tokenizer_exact=false。实际服务商 usage 仍独立保留，未返回的缓存数据不填成零。

默认总预算仍为 131,072，可用 GPL_LLM_CONTEXT_TOKENS 按配置的模型容量调整；输出预留保持原值。实际树加统一规则与简短提问的测试请求估算输入为 43,176，输出预留 65,536，通过预检。超过预算仍明确报错，完整树不会被截断。这不是精确 tokenizer 计数，也没有用真实付费请求验证计费量。
