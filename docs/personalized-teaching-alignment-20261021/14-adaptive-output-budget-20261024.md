# 长输入下的输出预算修正

失败任务 94、95 在课件生成的首次模型请求前被本地预算检查拦截。输入估算为 76,026，应用总预算为 131,072，实际上还剩 55,046 可用于输出；旧逻辑却固定要求预留 65,536，因而拒绝发送完整请求。

普通请求和流式请求现在按剩余窗口分配最大输出：

`实际输出上限 = min(原请求输出上限, 应用总预算 - 输入估算)`

小输入维持原上限；显式设置的较小输出上限不会被提高。窗口不足以保留有效输出空间时仍在请求前停止，默认至少保留 4,096；原上限低于此值时按原上限检查。直接调用严格预检接口的行为保持不变。

完整消息、知识树、已完成章节和冻结分工不会为通过检查而删改，也没有扩大应用总预算。模型若实际返回截断响应，仍按原完整性校验处理，不发布残缺课件。token 数仍是应用估算，实际窗口限制由服务商执行。

验证：构造输入估算恰为 76,026 的请求，检查普通调用与流式调用实际发送的 `max_tokens` 均为 55,046、消息保持完整，并验证较小窗口、较小显式输出额度及空间不足时不发送网络请求。后端 489 项测试通过。本次未自动重跑用户的付费模型生成任务。
