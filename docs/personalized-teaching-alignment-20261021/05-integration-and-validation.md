# 05：模型 E——迁移、集成和验收

先读 [共同契约](00-common-contract.md)。E 负责让各模型输出形成同一条真实闭环，不能只把各自测试通过当作产品已完成。本文件是后续实施验收方案，本轮未运行这些检查。

## 阶段与依赖

### 阶段 0：一次冻结

由 A/B/C/D/E 共同确定：状态枚举、TeachingManifest v2、完整树快照、父边方向、内容 hash 口径、action_id/撤销规则、表与归档顺序、API DTO 与兼容策略、各文件归属。

建议新增一组 shared fixtures，包含输入树、正文、清单、用户动作及期望输出。Python 和 TypeScript 读取同一数据；Android 调用同一 TS 归约器。由 E 独占公共样例文件，A/D 提交样例需求。

### 阶段 1：可并行实施

- A：本地数据服务/API、树与证据、迁移。
- B：真实生成入口、同次清单、章节协调和提示词导出。
- C：按共同契约实现 Android provider，不等待桌面 API 完成。
- D：共享 TS 与 UI，先提供稳定接口和 mock 给 C。
- E：准备端到端样例、旧归档、调用计数和中断恢复验证。

### 阶段 2：合并接线

先合并公共类型与迁移，再合并生成和 UI，最后统一导出提示词、清理旧接口和跑跨端检查。大文件只由指定 owner 编辑；冲突不能通过随意保留一侧解决。

### 阶段 3：真实验收与交付

功能、数据迁移和环境检查完成后，统一打包、更新本机安装与快捷方式，按 AGENTS.md 验证。若推送，按仓库要求检查对应提交的 CI，不能以 push 成功代替通过。

## 核心用户场景

| 场景 | 通过标准 |
| --- | --- |
| 新建“cpp基础语法到进阶应用” | 识别并关联规范 C++ 根，重启仍存在；识别失败如实待处理 |
| 再创建另一个 C++ 计划 | 复用通用根；不复制熟悉度，不因计划名产生新领域 |
| 逐步生成 STL、vector、多线程内容 | 正确主父关系；结构祖先不被当作已理解；不产生环/多父 |
| 父概念已经记录 | 同义名/领域匹配后复用已有父 ID，不重复创建 |
| 已有 C++，新讲 vector，缺 STL 容器 | 同次生成补 STL 容器，再接 vector；结构父无 quote 也可保存且熟悉度不升 |
| 新知识的父及祖先均未记录 | 自动补必要合理祖先链和领域根，不把小概念直接置根，不无限泛化 |
| 已有无父小节点，后来补出合理父 | 清单含 placement_changes，本地版本校验后自动挂接，不要求逐项批准 |
| 同一概念跨语言或项目同名 | 领域/私有作用域正确，不误合并、不串用私有证据 |
| 只有总纲未来目标 | 记录 planned，不能升级成讲过/学会 |
| 总纲真实讲解某个机制 | 该范围照常 recorded explained，可反馈理解，不因文档格式强制 planned |
| 同次生成课件或回答 | 正文与清单来自同次响应，清单含归属、范围和完整术语候选 |
| 问“vector 为什么迭代器失效” | 记录提问接触；不因此断言 vector 基础不会，不自动改长期风格 |
| 用户标“已完成”与“已理解” | 两种事实分开，反馈零模型调用，来源/范围可追溯 |
| 用户只理解 vector 基本访问 | 不自动确认扩容、STL 整体、实现或调试能力 |
| 后续问新范围或明确重讲 | 新范围/用户要求得到正常展开，不被同名概念去重吞掉 |
| 用户无额外要求 | 没有默认深度/术语密度/原理优先等固定指令，模型按任务决定 |
| 四章节并发 | 每章收到完整相同职责表和树版本；重试不混计划 |
| 课件最终拼接 | 以实际清单审计覆盖；链接根据最新树生成，最后章节术语不丢 |
| 点击术语解析 | 普通 QA，有来源和版本，响应继续进入同样清单/反馈闭环 |
| 旧配置/旧归档导入 | 不能关闭个性化，也不能恢复偏好/诊断的现行画像影响 |

## 必须做的故障与竞态验证

1. 并发两份清单新建同一概念：只有一个规范身份，父边不重复。
2. 一个网络请求重试三次：只有一份有效反馈；撤销后新动作重新确认有效。
3. 用户反馈时文档已重生成：旧 hash/片段被拒绝，不污染新版本。
4. 生成期间另一窗口修改理解状态：最终标注读取最新 state_version；并发变化触发本地重算。
5. 同概念来自两个课程：删一个来源只撤销其证据，另一个仍有效。
6. 模型/API 完全不可用：已校验内容的理解、取消、课程完成仍可本地更新。
7. 正文有了、清单缺失/无效：不伪装完整成功，不在确认按钮里偷偷调用模型。
8. 杀进程发生在文件写入、manifest 入库、反馈提交、状态投影之间：重启可恢复或清楚回滚，不重复累计。
9. 重置画像或删除来源时旧任务尚未完成：迟到结果不得复活已撤销状态。
10. 旧 observer、diagnostic pending、QA postprocess 队列恢复：不能执行退役写入。
11. 流式 chunk 把 TEACHING 标记/JSON 拆开：正文不泄漏元数据，清单不丢。
12. 代码块内出现 TEACHING: 示例、正文含引号/尖括号：解析不误截断，quote 验证正确。
13. 两个任务同时补同一个父/祖先：身份和父边不重复；同时给已有节点提出不同父时，过期提案不覆盖当前权威边，冲突可追溯。

## 大树、缓存和“全部术语”验证

- 准备 1,000、10,000 个概念的完整树。检查上传 ID 集合与可见树一致，而非只看提示词中存在 tree 标签。
- 相同树版本序列化完全稳定；仅改状态不扰动拓扑部分；追加节点与重挂时正确增版本。
- 记录最终请求输入估算/真实 token、模型/接口、缓存 usage 是否可用。未返回缓存字段写未知。
- 超预算不静默删节点；明确提示并采用约定的无损精简或停止策略。
- 构造每章超过 20 个有效不同术语、最后章节继续新增术语，逐项验证候选和可点击集合。
- 同一段多个陌生术语不被旧每段 1/2 配额隐藏；不因全文 12/20/24/30 上限丢失。
- 验证代码块、现有链接、行内代码、中文边界、命名空间、表格、标题和重叠名称。
- “模型返回了 N 项”不能证明完整；针对已知样例比较期望技术概念集合和最终标注集合。

## 迁移与往返

准备脱敏旧数据，包含：无事件的先验、人工已会/不熟、课程完成、理解总结、局部/部分理解、撤销、诊断和 Observer 假设、多父/循环关系、缺清单文档、旧 false 开关、旧偏好和原文要求。

验证：

1. 新装、旧版原地升级、重复启动、迁移中断重跑。
2. 桌面 → Android → 桌面往返，概念 ID/父边/状态/范围/来源/撤销/原文要求不丢。
3. 无证据先验仍未知；旧诊断与风格不会重新进入新决策；原有用户明确声明仍保留。
4. 不默认 AI 扫描所有旧课件；历史补录由独立入口执行，失败不影响已保存旧正文。
5. 导出不含 API Key；新表按外键顺序处理，旧格式有清晰兼容行为。

## 检查实际调用，而非函数是否存在

全仓检索并追踪运行入口：旧开关、renderPreferenceDirectives、inferPreferenceSignals、diagnostics、survey、defer_metadata、reindex_document、termMetadataInstruction 的数量参数、terms 截断、planner 缓存。

每一处保留命中要说明是历史兼容、正常总纲问卷、用户主动练习，还是实际执行路径。测试/历史说明里的词不能当作活动功能；活动调用也不能因为 UI 被删就漏检。

至少保存三类证据：

- 完整最终请求的脱敏结构摘要与包含概念 ID 集合。
- 按任务类型计数的模型调用：正文、必要课件规划、显式修复；理解/撤销/完成必须为零。
- 最终存储的概念、覆盖、证据、版本、标注与 UI 展示一致。

## 验证命令与环境

CI 当前要求 Node 22、pnpm 10.16.1、Java 21，见 .github/workflows/pr-validation.yml；以实际开工时配置为准。

后端在 backend 工作目录，以包含 app 的 PYTHONPATH 和已安装依赖的 Python 运行 unittest discover -s tests -v。Windows 使用实际可用的解释器，不盲抄 Linux 的 .venv/bin/python。

前端与 Android 按现有链执行：

~~~text
pnpm --dir frontend exec tsc --noEmit
pnpm --dir frontend run test
pnpm run frontend:build
pnpm run mobile:sync
~~~

Android 目录内执行 gradlew.bat test、assembleDebug、lint；补充真实设备/模拟器的数据库迁移、原生流和恢复验证。

先做各自必要定向测试，合并后统一完整测试；无新增变更/失败时不反复重复全量。用本轮实际结果报告，不能引用旧文档的通过数量充当新验证。
