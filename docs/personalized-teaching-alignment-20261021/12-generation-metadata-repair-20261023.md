# 生成元数据修复：知识清单不再让整篇正文失败

## 现象

生成项目总纲时任务直接失败，报错：

```
知识清单未就绪：coverage quote 必须在最终正文唯一定位。旧文档已保留。
```

正文已经生成完毕，却因为一条知识清单引用无法“唯一定位”而整篇丢弃，用户看不到任何新总纲。

## 用真实模型复现

用同一项目（`XY-729-cpp-kv-workbench`）和当前配置的模型重放一次总纲生成，失败原因可以精确定位为三类：

1. **标点改写**：清单引用的句子与正文只差一个标点。
   正文是 `停止时不再接收新任务、完成已经提交的任务`，清单写成 `停止时不再接收新任务，完成已经提交的任务`；
   另一条引用的句末是 `；`，清单写成 `。`。旧规则要求逐字节相同，因此判定“找不到”。
2. **同一段文字出现两次**：总纲分 `project_map.md` 与 `outline.md` 两个文件，同一句讲解常在两个文件里都出现；
   术语引用（如 `tests/core_tests.cc`、`tests/async_tests.cc`、`tests/service_tests.cc`）也会在项目地图表格和课程说明里重复。
3. **系统自己制造的重复**：总纲保存前会追加“按课生成课件”链接，链接文字逐字包含课程标题。
   于是引用课程标题的条目在写盘后变成出现两次，校验通过、入库时才失败。

另外还遇到两类身份字段问题：模型给出冻结知识树里不存在的概念编号；已有概念的 `domain`/`scope` 与知识树不一致。

## 修复规则

正文与知识清单的职责分开：**正文永远保留，清单只保留能被正文证实的内容。**

- 引用先在可见正文里逐字查找；命中一次即原样使用。
- 出现多次时，用引用自身的上下文扩展到只出现一次的连续片段；返回的仍是正文原文。
- 一次都没命中时，忽略标点与空白差异再查找一次；命中即替换为正文中的真实字符。字母、数字、`_ - / . |` 和汉字仍然必须一致，因此同义改写不会被误认。
- 仍然无法定位的条目不猜测：从清单中移除并记录日志，正文照常发布。
- 术语还要求原词在定位到的片段里只出现一次，避免 `session.cc` 与 `async_session.cc` 这类子串歧义。
- 已有概念的 `domain`/`scope`/`scope_id` 以知识树为准；不在冻结树中的概念编号被清除，由服务端按规范名与别名重新绑定。
- 冻结目录里不存在的范围编号被清除，避免一处编号错误阻塞整篇发布。
- 追加“按课生成课件”链接后，重新对最终写盘内容定位一次引用。

严格校验仍保留在发布与索引环节：写入文件的知识清单必须逐字唯一定位，无法证实的内容不会进入知识树，也不会改变熟悉度。

## 验证

- 新增 `backend/tests/test_manifest_quote_repair.py`：11 项，覆盖标点定位、重复引用扩边、术语子串歧义、无法定位时移除、双文件总纲与课程链接、概念编号与范围编号对齐。
- Python 后端全量测试：481 项通过。
- 用真实失败响应重放项目总纲任务：两个文件均发布成功，知识清单状态 `valid`，索引状态 `complete`，17 条讲解范围、119 个术语入库。
- 修复前后对比：同一条响应在修复前失败于 `coverage quote`，修复后总纲正常生成。

## 与既有规则的关系

`quote 必须真实、唯一定位` 没有放宽：放宽的只是“模型引用与正文的字符级差异”和“清单条目的取舍”。写入正文的引用必须能在正文中唯一定位，仍是入库前提。
