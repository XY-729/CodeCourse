# 只补清单、复用正文

## 修复的缺陷

旧补录入口把“有合法 v2 结构，但包含 metadata_gaps”的文档当成清单完整而直接复用，随后应用会失败。分段补录没有断点缓存；提示词还同时包含“先输出完整 Markdown”和“只输出清单”的相反要求。此前保住正文的修复不能单独解决这些问题。

现在只有不含缺口的有效清单才直接复用。缺口通过来源文档的 generation_id 找到同次冻结计划和原始章节响应，逐字验证章节仍存在于当前正文后，只提取这些章节。已通过的章节保留；不能唯一定位、原文已变或冻结身份不存在时，在模型调用前停止。

章节补录返回单独的 JSON 清单。模型使用 r1、r2 等本章短编号返回证据，不填写 UUID、职责编号、aspect 或 dimension；这些字段由软件按冻结计划绑定。已有概念的名称、领域、作用域和祖先以知识树为准。未实际覆盖的职责、无法定位的引用、越过章节的编号均不能清除缺口。

JSON 模式按 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/json_mode/) 使用 `response_format={"type":"json_object"}`。它不代替本地语义与引用校验。补录每次仅请求一次，最多预留 16,384 输出 token；官方 DeepSeek 的补录请求关闭推理，避免把提取预算花在隐藏推理上。不支持该输出参数的兼容服务会报错，不自动付费切换协议再试。

## 断点与费用控制

- 请求前保存完整冻结上下文、分段边界与来源身份。缓存按来源路径、正文哈希、协议版本、模型与服务地址隔离，不包含 API Key。
- 每段响应先落盘，再校验。已通过段在后续预览中复用；普通重开不会重发坏响应或结果未知的中断请求。
- UI 的“仅重试失败清单段”是显式再次请求入口，仅重发失败和未完成段；已通过段不重发。桌面功能不会向 Android 展示不具备的断点承诺。
- 同一文档并发预览使用同一把锁，避免重复点击产生重复模型请求。每次真正请求前再次确认原文未变，并在第一段请求前检查所有待请求段的预算。
- 历史长文按不重叠的原始段落切分；不会用重叠窗口重复抽取相同内容。
- 缓存完整时，即使用户关闭模型或移除 Key，也能在本地完成预览。完整覆盖只存入 sidecar override，正文保持原样，应用和再次应用均可重复安全执行。
