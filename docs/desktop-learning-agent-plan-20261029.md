# CodeCourse 桌面学习 Agent 开发计划

日期：2026-10-29

状态：开发规划，尚未实施

范围：Windows 桌面端，Electron / React / FastAPI / SQLite

优先级：父子对话与上下文管理优先，工具循环后置。Android 的功能实现、数据迁移和打包暂不纳入。

## 1. 目标与第一版完成标准

产品模型：每个项目有一个主对话，每个课件有一个持久子对话。课件正文是对话关联的产物，一次提问、生成或改写是一次任务。

第一版必须实现：

1. 在课件 A、B 之间切换时，各自恢复对话、当前分支、草稿和未解决问题；应用重启后继续。
2. 子对话继承项目学习目标、用户明确要求及相关知识状态；近期聊天和分支摘要相互隔离。
3. 早期重要要求不会因超过最近几轮而消失；长期记忆能够追溯到原始消息。
4. 子对话向主对话提交有来源的进展；“讲过、读完、明确反馈理解”分别记录。
5. 旧问答、课件、收藏、高亮和知识记录完整保留；导出、导入后恢复新增数据。
6. 现有课程生成器继续使用，保留成功章节复用、失败保留旧正文和知识清单校验。

第一版交付点为 M0—M3。M4—M5 增加可靠的多步骤执行与自主查证，构成后续 Agent 版本。

## 2. 范围与既有约束

- 增加对话身份、课件身份、统一上下文装配、结构化记忆、项目进展承接和桌面交互。
- 复用现有知识树、教学索引、证据服务和课程生成工作流；理解状态继续使用现有权威记录。
- 工具阶段优先提供只读查证。课程生成通过现有生成入口、确认语义及发布管线完成。
- 保留当前材料附带规则、模型设置和费用提示；工具不能扩大本轮允许读取的范围。
- 维持 AGENTS.md 的主题、配色、层叠工作区和调整大小约束。新状态接入现有助手、历史和任务区域。
- 本轮不包含自主修改导入仓库、运行仓库代码、终端执行、联网搜索或多 Agent 协作。
- 此次只产出计划文档。后续应用实现批次按 AGENTS.md 完成桌面打包、本机更新、快捷方式及安装一致性验证。

## 3. 当前基础与缺口

以下为计划编写时的工作区实现。实施前核对差异，保留已有未提交工作。

| 当前实现 | 可复用基础 | 需要补齐 |
| --- | --- | --- |
| qa_sessions、qa_records | 会话、追问边、问答落盘 | 项目主对话、课件子对话及稳定归属 |
| qa_service 的会话上下文与记忆更新 | 近期历史和摘录 | 祖先链隔离、长期记忆、去重和预算 |
| GenerationContext、outline_forest | 冻结知识树、状态、要求、总纲绑定与指纹 | 接入每次问答的 ContextBundle |
| generation_service | 章节计划、职责冻结、校验、缓存和补漏 | 绑定稳定课件、对话及统一任务 |
| code_intelligence、检索索引 | 文本、符号、结构及调用链查证 | 工具 schema、授权范围和调用协议 |
| qa_background、teaching_index、publication | 幂等后处理、证据与恢复发布 | 对接取消、版本冲突及记忆失效 |
| data_transfer | 备份恢复 | 新身份、记忆、报告的归档与版本兼容 |

需要正面解决的现状：

- 子回答复用父回答的 session_id；按 session 读最近历史会混入兄弟分支。
- 当前会话记忆主要摘录最近六轮，每条回答截取约 220 字，不能承担项目长期记忆。
- CourseFile 主要以 filename 标识；课序、路径和可清理的教学索引不适合作为永久课件身份。
- QA 主路径是准备上下文、单次模型调用、保存；旧 observer/planner 代码不能视为活动 Agent 循环。
- 存档导入清空普通数据表后只恢复白名单；新持久数据必须与归档和格式迁移一起交付。

## 4. 核心模型与数据归属

~~~text
Project
  └─ 主对话：学习目标、明确要求、项目级进展
       ├─ 课件 A 子对话：消息分支、记忆、疑问
       │    ├─ 稳定课件身份 → 正文修订及教学索引
       │    └─ 一次任务 → 上下文快照 → 执行步骤 → 产物
       └─ 课件 B 子对话
~~~

下面是逻辑对象；表名在 M0 统一，身份与归属规则保持一致。

| 对象 | 核心字段或约束 | 阶段 |
| --- | --- | --- |
| LessonIdentity | UUID、project_id、kind、当前路径、所属总纲、状态、当前修订；独立于课序和路径 | M1 |
| Conversation | UUID、project_id、parent_id、scope、lesson_id、active_head_qa_id、state_version；项目唯一主对话，每课件唯一默认子对话 | M1 |
| QA 绑定 | 现有 qa_records 增加 conversation_id；保留 QA ID、parent_qa_id、兼容 session_id | M1 |
| LessonRevision | lesson_id、revision、content_hash、teaching_document 引用、正文快照引用、来源任务 | M1 |
| MemoryCheckpoint | conversation_id、head_qa_id、through_qa_id、schema_version、结构化状态、来源、版本 | M2 |
| LessonReport | lesson_id、conversation_id、canonical_head、来源修订、增量、来源、有效状态、版本 | M2 |
| ContextBundle | 请求/分支、材料清单、授权快照、记忆/知识/课件版本、预算、策略版本和 hash | M2 |
| AgentRun / RunStep / RunEvent | 幂等键、状态、attempt epoch、步骤结果、用量、事件序号、上下文引用 | M4 |

数据规则：

1. 会话父子关系与消息父子关系分别校验。课件属于主对话，不意味着默认读取主对话的全部消息。
2. QA 消息以 qa_records 为唯一权威来源；第一版不复制另一套可独立编辑的 messages 表。
3. 稳定课件身份覆盖总纲、分课和手工课件。源码问答默认进入主对话；明确从课件发起时可留在该子对话。
4. 重命名、同课再生成保留 lesson_id、增加修订；删除保留墓碑与可读历史；同路径重建新课获得新身份。
5. 总纲重排通过持久绑定承接；有歧义时新建实体并保留旧关联，不按标题相似或“第几课”自动继承。
6. teaching_documents 继续承担教学索引和当前内容校验；稳定课件引用它，不以该可清理记录代替身份。
7. 修订原文优先复用已有可靠 publication 内容；不足时保存到项目生成目录内的专用版本目录，一同归档。
8. 来源引用含消息/文档 ID、内容 hash、适用项目和材料授权类别；编辑、删除、撤销反馈后可定位受影响记忆。

## 5. 上下文与记忆规则

### 5.1 每次请求的 ContextBundle

后端 ContextBuilder 统一装配：

1. 系统协议、本轮问题和用户明确要求。
2. 项目共享状态、与当前分支相容的课件记忆。
3. 当前消息祖先链上的近期问答。
4. 现有范围规则确定的完整知识森林与学习状态。
5. 本轮允许的选区、附件、课件及源码证据。
6. 工具阶段产生的、仍在授权与预算内的观察结果。

每块记录来源、版本、作用域、纳入原因、估算 token 和授权类别。调用使用不可变快照；诊断默认只输出材料身份及用量，不输出密钥和整段请求正文。

历史按当前 head 的祖先链读取，不取整个 session 最近 N 条。跨项目/跨课件异常父边拒绝读取并标记待修复。

记忆同步隔离：checkpoint 的 through/head 必须属于当前祖先链。兄弟摘要不能通过 conversation 级缓存混入。来源编辑或删除后失效并按有效来源重建。

### 5.2 长期记忆与项目回传

结构化状态至少保存：目标、明确约束、当前主题、已讨论结论、未决问题、下一步及来源。

- 原始消息和修订保留，摘要可重建；增量更新处理新增消息，不反复只保留最近几轮。
- 明确要求保留原意及来源；新要求替代旧要求时记录 supersedes 关系。
- 第一版复用教学交接和同次回答元数据；MemoryDelta 通过结构、来源、范围和版本验证后入库。
- 不重启已退休的 observer/planner 二次推断链，不为每轮固定新增一组分析调用。
- 超预算时才触发可缓存摘要维护；失败不破坏回答、原文及旧记忆，维护状态明确可查。
- 子对话只回传正式报告：进度、稳定结论、跨课未决问题及来源。草稿分支不自动成为项目共识。
- 正式报告来自当前发布产物、明确学习反馈或当前主分支的完成结果；不新增每轮手动确认。
- 报告替换/撤销采用版本增量；父级通过短事务/CAS 合并，冲突时重读合并，不覆盖其他课的新进展。
- 讲解记录进入覆盖，读完记录进入完成；理解状态继续由反馈与证据服务决定。
- 第一版父级读取各课结构化报告；其他课完整聊天和正文留待检索按需取用，不整体复制。

### 5.3 预算与材料范围

- 预算含输入、输出预留与后续步骤余量；复用已有预检，记录估算方法与实际 usage。
- 优先去重、移除可重取的冗余工具结果、压缩旧对话；硬性要求、知识事实及证据引用不静默丢失。
- 保留已选知识森林完整性和范围规则，继续紧凑表示，不改为按问题关键词随意裁树。
- 必需材料仍超限时停止本轮并保留已有结果，说明具体不足；不能截断知识树后冒充完整输入。
- 稳定前缀与动态问题/结果分开组织；不为缓存命中固定发送无关历史。
- include_context=false 沿用问题、选区、允许记忆和明确附件规则，不自动读当前文档与全仓。
- context_files 独立生效，只允许明确附件，不扩到相邻文件或依赖。
- include_context=true 冻结当前项目及材料范围；所有工具校验后端 ToolScope，模型参数不能改变授权。
- 宽范围读取产生的摘要携带来源类别；记忆、报告和缓存不能绕过本轮材料范围。

## 6. 分阶段任务与退出条件

### M0：协议与验收样例

交付：数据关系、上下文契约、身份生命周期、材料范围及迁移方案。

- [ ] 固定第 4 节对象、唯一约束及当前分支 head 语义。
- [ ] 固定来源引用、MemoryDelta、LessonReport、ContextBundle 的版本化 schema。
- [ ] 确定项目问答、源码问答、课件追问、术语解释和替代讲解的路由。
- [ ] 构造空库、单课旧会话、跨课旧会话、分支和无来源历史的临时库 fixture。
- [ ] 固定消息数量/正文 hash、课件 hash、分支边、知识状态、调用数及缓存复用基线。
- [ ] 设计上下文与工具两个独立开关；关闭新功能保留数据，不靠删表降级。

退出：关键行为有确定契约与样例，不依赖模型猜测历史归属。

### M1：稳定身份、父子对话与迁移

交付：数据库/API 支持新身份；旧数据和备份兼容；沿用现有问答执行器。

- [ ] 新增课件登记、修订引用、Conversation、QA 归属字段及数据库唯一约束。
- [ ] 生产迁移前暂停写任务，用 SQLite 备份 API 等方式生成包含 WAL 有效内容的一致性快照，并备份课件/修订文件；记录版本、路径和校验结果，验证可还原。备份失败不开始迁移。
- [ ] 接入创建、改名、再生成、删除、总纲重排和同路径重建，验证身份生命周期。
- [ ] 旧项目建立主对话，现有课件建立身份和默认子对话；迁移事务化、可重入并输出报告。
- [ ] 明确单一来源且祖先一致的历史可确定绑定；跨课或冲突历史原样保留为 legacy 只读引用。
- [ ] 保留 session_id、QA ID、父边、原文和文件位置；不按 active_source_path 归整段旧历史。
- [ ] 增加对话解析/查询接口及提问字段；conversation_id 与 parent_qa_id 矛盾时返回冲突。
- [ ] conversation_id 作为新路由的权威身份；过渡期为新对话分配唯一兼容 session，将原锁、流式 key 和旧响应绑定到该对话，避免再次共用旧 session。歧义 legacy 历史保持原关联。
- [ ] 更新删除项目/问答/课件及清理流程，避免孤立引用和后台重建。
- [ ] 桌面存档写 v2、兼容读 v1/v2；新表、修订原文进入归档，v1 导入后运行同一迁移。
- [ ] v2 能力在桌面后端定义；不提升 Android 使用的共享导出版本常量，避免旧端误写不完整 v2。
- [ ] 旧客户端明确拒绝 v2；导入前校验全包及引用，失败时数据库与文件共同回滚。

落点：storage.py、models/schemas.py、qa.py、课件生命周期/发布入口、data_transfer.py；新增独立 conversation、lesson identity 服务。

退出：旧数据核对一致；重复迁移不增加实体；导出→全新库导入→再导出保留身份、消息边、修订及墓碑。

### M2：上下文隔离、长期记忆与项目承接

交付：后端支持父子状态继承、祖先链历史、结构化记忆和正式报告。

- [ ] 实现 ConversationResolver 及祖先链历史；缺省 head 由后端解析并返回最终归属。
- [ ] 实现 ContextBuilder、ContextPolicy、去重、预算和不可变 ContextBundle。
- [ ] 接入历史、选区、附件、知识森林和检索证据；复用 GenerationContext 版本与范围约束。
- [ ] 实现分支兼容 MemoryCheckpoint，记录来源、through/head、版本和失效重建。
- [ ] 实现增量记忆、要求替代关系、LessonReport 和父级版本合并。
- [ ] 编辑/删回答、撤销反馈、课件修订后撤销或降级受影响结论，保留来源。
- [ ] MemoryDelta、checkpoint、报告写入前，在事务内校验来源消息 hash、课件修订、有效 head 和目标实体存在性；失配时丢弃或重算，防止失效后被迟到维护任务重新写回。
- [ ] 普通 QA、术语、替代讲解、流式追问及后台后处理使用同一归属和上下文规则。
- [ ] 提供开发诊断入口，展示来源清单、版本、预算和排除原因。

落点：qa_service.py、qa_background.py、continuity_service.py、generation_context.py；新增 context builder、memory、report 服务。

退出：20—30 轮合成对话保留早期要求；课件及兄弟分支无未授权串话；报告可追溯、撤销和重建；不产生虚假理解证据。

### M3：桌面接入与第一版交付

交付：现有桌面工作区可以使用项目主对话及课件子对话。

- [ ] 助手显示所属项目/课件和对话入口，历史按归属访问，保持原工作区。
- [ ] 打开课件恢复其对话/草稿；项目入口进入主对话；源码阅读不无意切走明确追问。
- [ ] 分开处理选中历史、切阅读标签和明确追问；切标签不改变已提交请求。
- [ ] 按 conversation_id 保存草稿、head 与界面状态；提交时冻结目标和材料。
- [ ] 流式事件及回调绑定提交时的对话；浏览另一课时结果仍回到原对话。
- [ ] 保留旧历史、收藏、编辑、返回原文、术语和继续学习入口。
- [ ] 沿用后端活动回答保护，明确可浏览及需等待的操作，同对话重复提交有保护。
- [ ] 展示项目进展和本课未决问题，可回到来源，不增加逐轮摘要确认。
- [ ] 桌面打包、本机更新、快捷方式及包/安装文件一致性验证。

落点：api/client.ts、app/useAppController.ts、app/qaConversation.ts、QA hooks、现有助手/历史视图、工作区持久化。

退出：A01—A10 通过。M0—M3 可单独交付，工具能力不阻塞这一版。

### M4：可靠运行时与原工作流接入

交付：为连续工具调用提供持久任务、取消、重试和恢复基础。

- [ ] 建立 Run/Step/Event，以 project_id + client_request_id 唯一约束，保存规范化请求 hash。
- [ ] 同 ID 同内容返回原任务，不同内容返回冲突；一份最终回答及一组有效知识写回。
- [ ] 定义 queued/running/cancelling/cancelled/completed/failed/interrupted 状态和合法迁移。
- [ ] 持久化单调 event seq，SSE 按 cursor 回放；重连不重新提交模型请求。
- [ ] 同子对话一个写任务，项目级限制总并发；冻结 head、父状态、课件及知识版本。
- [ ] 取消先持久化，关闭可关闭的连接、停止新步骤、撤销旧 attempt 的提交资格。
- [ ] 文件发布、QA 完成、报告和知识写回前检查 run、epoch、来源版本及项目存在性。
- [ ] 短事务/版本比较处理合并，模型等待期间不持有 SQLite 写锁。
- [ ] 重启将未完成调用标记 interrupted；复用已持久化成功步骤，结果未知调用不自动重发。
- [ ] 每次供应商请求 attempt 均持久记录并计入预算；审计底层 HTTP 自动重试，仅确定未发送或明确可安全重试的拒绝可自动重试。已发送但结果未知时，不允许底层通用重试静默重发。
- [ ] 恢复界面说明未知调用重试可能再次计费，不承诺供应商模型调用 exactly once。
- [ ] 将现有章节生成适配为完整工作流，保留计划冻结、章节缓存及可靠发布。
- [ ] watchdog 超时撤销提交资格，迟到线程不能把失败/取消任务改为完成。

取消保证停止新步骤、阻止迟到写回和状态一致；供应商已收到的请求可能继续计费。

退出：故障注入下无重复发布/证据；取消后旧线程无法提交；重连不增加调用；成功章节继续复用。

### M5：只读工具循环与 Agent 版本交付

交付：证据不足时自主查证，材料齐备时直接回答。

- [ ] 首批工具为 search_project、read_source_range、trace_symbol、find_prior_explanation；按需接入课件修订读取。
- [ ] 固定参数/结果 schema，结果含来源、行号/片段、hash、索引版本及覆盖限制。
- [ ] 每次校验 ToolScope、项目、路径、运行状态及预算；工具文本只作材料。
- [ ] 模型适配器支持原生 tool_calls、结果角色、调用 ID、参数验证及流式拼装。
- [ ] 按端点/服务商/模型能力配置选择模式；不支持工具则降级现有确定性检索与普通流式问答。
- [ ] 认证、限流、超时按真实错误处理；已有工具或部分结果时不静默重启整轮。
- [ ] 限制工具回合、调用数、总时长、token；初始可配 3 回合/6 次调用，再按验收调整。
- [ ] 原子计算“已消耗＋在途预留”，覆盖并发章节、每个供应商 attempt 和重试；调用前预留、按 usage 结算，未知用量不记零，到上限时有依据地收束。
- [ ] 工具与生成缓存分开；key 含端点/模型、提示词/工具版本、生成配置、授权范围、材料/索引版本。
- [ ] 最终回答和必要过程事件持久化，工具全文不整体升级项目记忆。
- [ ] 接入现有进度、停止、恢复入口，完成桌面回归及安装交付。

退出：A11—A15 通过；简单问答不强制检索；无工具模型继续支持父子对话与长期记忆。

## 7. 实施组织与依赖

主依赖：M0 → M1 → M2 → M3（第一版）→ M4 → M5（Agent 版本）。

- M0 后可并行身份迁移和桌面交互原型；原型使用冻结接口及合成数据。
- M1 后上下文与记忆/报告可分工；来源、分支兼容及版本合并使用统一契约。
- M4 前只准备工具 schema 和模拟服务，不启用连续调用。
- 分批实施上下文、迁移和运行控制；每批有独立行为、必要回归及可评审结果。
- 实施前核对已有生成缓存、提示协议和测试改动，逐项整合，保留其他未提交工作。
- 应用实现批次遵守桌面交付要求；归入同一发布批次的内部提交在批次验收后统一打包。
- 功能关闭保留新增数据；旧程序回退通过迁移前备份恢复，不让旧可执行文件直接写新结构库。
